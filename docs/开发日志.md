# ReliSign 智能手语识别系统 · 项目开发日志

> **项目名称**：ReliSign 智能手语识别与翻译系统（基于 Uni-Sign 底座二次开发）
> **开发周期**：2026-03 ~ 2026-07
> **面向赛事**：iCAN 创新创业大赛
> **项目定位**：面向听障群体的公共服务辅助沟通工具——将连续手语实时翻译为文字，并可播报语音、双向交互。

---

## 0. 项目要解决什么问题

听障人士在医疗问诊、政务办事、校园、银行商超等公共服务场景中沟通困难。本项目构建一个**可实时演示的连续手语识别系统**：

- 摄像头采集手语 → 姿态关键点提取 → 深度学习模型 → 中文文字翻译 → 语音播报
- 从「论文模型」走到「可现场演示、可部署、可双向交互」的完整系统

## 2. 分阶段开发日志

### 阶段一：方案设计与技术选型（2026-03）

**方案设计**
- 调研对比后确定：不从头训练模型，而是基于 ICLR 2025 开源框架 **Uni-Sign** 做二次开发。
- 理由：Uni-Sign 已具备姿态主干（ST-GCN）+ mT5 多语言解码 + Pose/RGB 双路线，且自带在线推理脚本，适合快速落地。
- 明确「研究价值 + 应用价值」双线：技术线 = 可靠性感知多模态融合；应用线 = 听障公共服务辅助沟通。

**关键决策**
- 选定低资源中文连续手语数据集 **CE-CSL** 作为落地场景（而非英文大规模数据集）。

> 📎 佐证：`docs/archive/legacy_docs_2026-04-17/research/02_选题与路线/论文方向与文献清单_2026-03-31.md`

---

### 阶段二：核心算法引擎搭建（2026-04 上旬）

**方案设计**
- 完成 CE-CSL 数据适配（格式、标签、姿态文件、路径、训练入口）。
- 建立本地训练入口 `local_sign_tools/finetune_cecsl_rgb_support.py` 和评估入口 `script/eval_cecsl_samples.py`。

**实验测试**
- 跑通 `pose-only + SLT`（纯姿态 + 手语翻译）主链路，确认「可训练、可评估」。

**问题排查与解决**
- 低资源数据（数百条样本）直接沿用原论文大学习率（3e-4）会过拟合 → 降到 3e-7（约 1000 倍），稳定收敛。

> 📎 佐证：`README.md`（Training & Evaluation 一节）、`local_sign_tools/`

---

### 阶段三：多模态融合与模型迭代（2026-04 中旬）

**方案设计**
- 引入手部 RGB 辅助分支：手部裁剪 112×112 → EfficientNet-B0 提取细粒度特征。
- 提出两项核心改进：
  1. **置信度引导的手部关键帧选择**（confidence_topk / weighted / uniform / random 四种策略）
  2. **可靠性感知 RGB-pose 融合门控**（用置信度/采样密度/手部存在率驱动，动态调节 RGB 贡献）

**版本迭代（模型）**
| 版本 | 说明 |
|------|------|
| round3 | 初版 RGB 训练（lr=1e-7，未充分收敛，eval_loss 5.60） |
| round6 | 最佳模型（lr=3e-7，20 轮长训练） |
| round7 | round6 基础上 4 轮短 refine（出现轻微过拟合） |

**实验测试**
- round6 在 Test100 上：AvgSim 0.3528、BLEU-4 11.19、ROUGE-L 34.23。

**问题排查与解决**
- 发现「直接加 RGB 不一定提升效果」——这驱动了后续可靠性感知融合的设计。

> 📎 佐证：`docs/01_项目总览/06_超参数训练实验完整记录.md`、`models.py`、`deformable_attention_2d.py`

---

### 阶段四：实验测试与验证（2026-04 中下旬）

**实验测试（50+ 组受控实验）**
- 学习率搜索：lr ∈ {1e-7, 2.5e-7, 5e-7, 1e-6} × 3 模型 = 12 组
- 随机种子稳定性：seed ∈ {42, 123, 456, 3407} × 3 模型 = 12 组
- 消融实验：9 组（pose-only / rgb_support / single_stage / conf_topk / conf_weighted / uncert_gate / gate_only / gate_no_meta / selection_only）
- mT5 学习率缩放、Stage2 轮数等

**核心结论**
- pose-only 是稳定强基线；可靠性感知融合能改善 RGB 分支并缩小与 pose-only 的差距。

**佐证数据（主结果表，Test100）**
| 模型 | AvgSim | BLEU-4 | ROUGE-L | WER |
| --- | ---: | ---: | ---: | ---: |
| pose-only | 0.3625 | 12.34 | 35.07 | 73.70 |
| naive RGB | 0.3575 | 10.61 | 34.34 | 75.28 |
| 可靠性门控 | 0.3620 | 10.62 | 34.81 | 74.91 |

> 📎 佐证：`out/paper_metrics/*.json`（11 个实验汇总 JSON）、`out/train_*.log`（训练日志）

### 阶段八：系统 v4 —— 实时演示系统与性能优化（2026-07）

**方案设计**
- 从「离线视频推理」升级为「摄像头实时手语识别」。
- 采用生产者-消费者架构解耦姿态提取与 WebSocket 通信。

**问题排查与解决（7 大技术难点，全部攻克）**

| 难点 | 问题 | 解决方案 | 效果 |
|------|------|---------|------|
| 大模型推理延迟 | 2.2GB 模型 CPU 推理 2-5s | 模型分层部署 + GPU + 贪心解码 | 0.3-0.8s |
| 姿态提取 CPU 瓶颈 | 80-120ms/帧卡顿 | onnxruntime-gpu + 降分辨率 + 独立线程 | 5-15ms/帧 |
| 多人检测混乱 | 骨架在多人间跳动 | 最大面积选择策略 | 自动锁定目标 |
| WebSocket 延迟 | 串行阻塞 | 生产者-消费者解耦 | 50-100ms 端到端 |
| 前端渲染 | 133 关键点渲染卡顿 | 关节点微型化 + 去阴影 + rAF | 60fps |
| 显存 OOM | 答辩切页显存爆炸 | 模型卸载/重载机制 + STT 强制 CPU | 2.21GB→自动释放 |
| 多页面资源管理 | 两模型抢显存 | 懒加载 + 独立缓存 + SQLite | 单进程 ~5GB |

**版本迭代**
- 系统定名 **ReliSign**，7 大功能模块：实时演示 / 模型展示 / 模型归因 / 智能学习 / 技术架构 / 应用场景 / 用户中心。

**系统性能指标**
- 端到端延迟 50-100ms；姿态提取 60-100fps；模型推理 0.3-0.8s；前端 60fps。

> 📎 佐证：`docs/01_项目总览/05_实时演示系统技术难点与攻克记录.md`、`view/启动说明.txt`、`docs/archive/research/连续手语识别系统技术难点攻克报告.md`
